# Governance

Open Chat Reviewer is maintained in public with a lightweight maintainer-led model.

## Roles

- **Contributors** report problems, improve documentation, propose designs, and submit
  pull requests.
- **Maintainers** triage reports, review changes, manage releases and security reports,
  and decide what enters the supported product.

Consistent contributors may be invited to triage or maintain parts of the project after
demonstrating sound technical judgment, respectful collaboration, and care with private
archive data. Access is granted narrowly and may be removed when it is no longer needed.

## Decisions

Routine decisions happen in issues and pull requests. Significant changes should begin
with an issue that records the problem, alternatives, privacy implications, migration
path, and maintenance cost. Maintainers seek rough consensus but retain final authority
to protect project scope, users, and release quality.

A contribution is not accepted solely because its checks pass. Maintainers may request
changes or decline work that weakens evidence provenance, source read-only guarantees,
archive privacy, migration safety, provider neutrality, operator clarity, or long-term
maintainability.

## Changes and releases

The protected `main` branch is the current source of truth. Changes arrive through pull
requests with required CI and resolved review conversations. Security fixes may be
prepared privately and disclosed after a safe release is available.

The project is currently alpha. Compatibility is valued, but interfaces may change when
the benefit and migration path are documented.

## Conduct and security

Participation is governed by [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md). Security and
sensitive-data reports follow [SECURITY.md](SECURITY.md).
